# LLM-VulnGen

**A Benchmark Dataset of LLM-Generated Web Vulnerabilities**

![Data License: CC BY 4.0](https://img.shields.io/badge/Data%20License-CC%20BY%204.0-blue.svg)
[![Code License: MIT](https://img.shields.io/badge/Code%20License-MIT-green.svg)](LICENSE-CODE)

LLM-VulnGen is a benchmark dataset for studying the security of code produced by Large Language Models in web development settings. It contains **1,080 code samples** generated by four contemporary LLMs across three web stacks, each labeled with the security vulnerabilities it contains.

> [!WARNING]
> **Responsible use.** This dataset deliberately contains insecure source code so that researchers can study, detect, and mitigate vulnerable LLM output. It is **not** a collection of working exploits and must not be deployed in production systems. See [Intended use and ethics](#intended-use-and-ethics).

## At a glance

| Property                   | Value                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------- |
| Samples                    | 1,080                                                                                 |
| Models                     | `Gemma3-27b`, `DeepSeek-7b`, `Mistral-7b`, `Phi4-14b`                                 |
| Languages                  | Python/Flask, Node.js/Express, PHP                                                    |
| Tasks                      | `search`, `login`                                                                     |
| Prompt strategies          | `quick_dirty`, `copy_existing`, `deadline_pressure`, `legacy_style`, `minimal_code`   |
| Temperatures               | `0.2`, `0.7`, `1.0`                                                                   |
| Generations per config     | 3                                                                                     |
| Overall vulnerability rate | 89.0%                                                                                 |
| Vulnerability classes      | SQL injection, XSS, command injection, path traversal, SSRF, insecure deserialization |

Design:

```text
4 models x 30 task-strategy prompts x 3 temperatures x 3 samples = 1,080 samples
```

## Quick start

```bash
git clone https://github.com/<your-username>/llm-vulngen.git
cd llm-vulngen
pip install -r requirements.txt

# Load the dataset and print a summary
python scripts/load_dataset.py

# Reproduce the aggregate statistics from the raw samples
python scripts/compute_statistics.py
```

Minimal loading example:

```python
import json

with open("data/dataset.jsonl", "r", encoding="utf-8") as f:
    samples = [json.loads(line) for line in f]

vulnerable = [s for s in samples if s["is_vulnerable"]]
print(f"{len(vulnerable)} / {len(samples)} samples are vulnerable")
```

Using pandas:

```python
import pandas as pd

df = pd.read_csv("data/summary.csv")
print(df.groupby("model")["is_vulnerable"].mean())
```

## Data schema

Each line in `data/dataset.jsonl` is one sample. Full descriptions are available in [`docs/SCHEMA.md`](docs/SCHEMA.md).

| Field               | Type            | Description                                               |
| ------------------- | --------------- | --------------------------------------------------------- |
| `id`                | string          | Unique sample identifier                                  |
| `prompt_id`         | string          | Identifier of the originating prompt                      |
| `model`             | string          | Generating model                                          |
| `task`              | string          | Web task, such as `search` or `login`                     |
| `language`          | string          | Target stack: `python`, `nodejs`, or `php`                |
| `strategy`          | string          | Vulnerability-inducing prompt strategy                    |
| `temperature`       | float           | Sampling temperature: `0.2`, `0.7`, or `1.0`              |
| `code`              | string          | Generated source code                                     |
| `vulnerabilities`   | list of strings | Detected vulnerability types                              |
| `confidence_scores` | dictionary      | Per-type detector confidence scores in the range `[0, 1]` |
| `is_vulnerable`     | boolean         | `true` if at least one vulnerability was detected         |
| `vuln_count`        | integer         | Number of distinct vulnerability types detected           |

## Intended use and ethics

**Intended uses.** Benchmarking and training vulnerability detectors; evaluating the security of code-generation models; studying how prompt phrasing affects security; and education on insecure coding patterns.

**Out-of-scope and discouraged uses.** Deploying any sample in a live system; using the dataset to produce exploits against real targets; or any use that violates the license terms of the underlying models.

**Why publishing insecure code is justified.** The vulnerability classes represented here, including SQL injection, XSS, command injection, path traversal, SSRF, and insecure deserialization, are long-documented vulnerability categories. The samples expose where current models fail, which is a prerequisite for building defenses. No personal data is involved, and no live system is targeted.
